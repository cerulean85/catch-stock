# 투자 도움 기능 아이디어

> 작성일: 2026-08-14
> 현재 코드베이스 기준으로 정리한 확장 아이디어 모음.

## 진단

이 앱은 **투자 "입력"은 강한데 "학습 루프"와 "능동적 신호"가 비어 있다.**

- **강한 입력:** RSI 스크리너, 키움 실계좌(잔고·체결), Gemini 리스크 평가, 마크다운 일지, 각종 메모(원칙/장중/스윙/리스크)
- **약한 부분:**
  - 이 입력들이 서로 연결되지 않음
  - 내 판단이 맞았는지 되돌아보는 피드백이 없음
  - 스크리너가 찾아가야만 보이는 수동 구조

## A. 학습 루프를 닫는 것 (가장 고가치)

### 1. 일지 "판단 → 결과" 채점 루프 ⭐ 최우선

스키마에 이미 `reviewAt` / `reviewedAt` / `linkedJournalId`가 있는데 **절반만 구현**돼 있음. 완성 방향:

- 매수/매도 일지 작성 시 **검토 예정일** 설정 → 그날 알림
- 검토 시 두 축으로 채점: **결과**(수익/손실)와 **과정**(논리가 타당했나 — 결과와 별개로)
- "과정은 좋았지만 운 나쁨" vs "운 좋았지만 근거 없음"을 구분 → 실력과 운을 분리
- 계좌 체결(`accountTrades`)과 자동 매칭해 실제 손익을 채점에 끌어옴

투자자를 실제로 성장시키는 건 이 루프. 스키마가 이미 있어 **가치 대비 노력이 가장 좋음.**

### 2. 매매 성과 분석 (실계좌 기반)

**한 줄 요약:** 체결 로그를 매수-매도 짝으로 묶어, 승률·손익비·보유기간 같은 실제 성과 지표를 내고, 일지와 대조해 내 매매 습관의 문제를 숫자로 드러내는 것.

#### 지금 있는 것 vs 없는 것

지금 `accountTrades`는 "언제 몇 주를 얼마에 샀다/팔았다"는 **날것의 로그**일 뿐. "그래서 내 매매가 좋았냐?"는 안 나온다.

있는 것 (`accountTrades` 한 줄씩):

```
2026-03-10  AAPL  buy   10주  @ 180
2026-05-02  AAPL  sell  10주  @ 210
```

없는 것 — 이 두 줄은 사실 **하나의 완결된 매매(라운드 트립)** → 실현손익 +$300, 수익률 +16.7%, 보유기간 53일. 체결 로그를 **매수-매도 짝으로 묶어(FIFO 등)** 청산 포지션 단위로 재구성하는 게 핵심.

#### 구체적으로 계산하는 것

1. **청산 포지션별 성과** (`side`, `quantity`, `price`, `fee`, `tradedOn`)
   - 종목별 실현손익(수수료 차감), 수익률
   - 보유기간 (매수일 → 매도일)
2. **전체 통계**
   - **승률** — 이익으로 끝난 매매 비율
   - **손익비(R)** — 평균 이익 ÷ 평균 손실 (승률 낮아도 R 높으면 남는 구조)
   - **평균 보유기간** — 내가 단타인지 스윙인지 실제 데이터로 확인
   - 국내/해외(`scope`), 통화(`currency`)별 분해
3. **일지 연결 — 이 앱만의 차별점**
   - `journals.tickers[]`로 청산 매매를 일지와 매칭
   - **일지를 남기고 한 매매 vs 그냥 지른 매매의 성과 비교** → 행동 편향을 숫자로 확인
     (예: "충동 매매의 승률이 20%p 낮다")

#### 기존 `/journal/stats`와 다른 점

현재 통계는 일지의 `sentiment`(기분/생각) 기반 추정. 이건 **실제 체결·실제 돈** 기반이라 신뢰도가 높다.

#### 확인 필요

키움 체결 데이터에 **수수료·세금이 매도 쪽에 온전히 들어오는지**에 따라 실현손익 정확도가 갈린다. 실제 데이터 한두 건을 보고 매칭 로직을 맞춰야 함.

## B. 리스크·규율

### 1. 포트폴리오 리스크 대시보드

**한 줄 요약:** 지금 보유 중인 종목들(`accountHoldings`)을 합쳐서 "내 돈이 어디에 얼마나 쏠려 있나"를 한눈에 보여주고, 위험한 편중을 경고하는 것.

#### 왜 필요한가

`/account` 페이지는 종목을 **하나씩 나열**만 한다. 하지만 리스크는 개별 종목이 아니라 **전체 구성**에서 온다. 개인투자자가 가장 과소평가하는 게 "나도 모르게 한 곳에 몰빵돼 있는" 집중 리스크다. 이걸 포트폴리오 단위로 합산해서 보여준다.

#### 지금 데이터로 바로 계산되는 것 (`accountHoldings`)

`evalAmount` / `evalAmountKrw` / `currency` / `scope` / `pnlAmount` / `pnlRate`로 즉시 가능:

1. **종목 집중도** — 각 종목 평가액 ÷ 총 평가액. 상위 종목 비중, "1종목이 40% 이상" 같은 경고
2. **통화·지역 노출** — 원화 vs 달러 비중 (환율 리스크), 국내(`domestic`) vs 해외(`overseas`) 비중
3. **손익 분포** — 미실현 손익(`pnlAmount`) 합계, 물려 있는 종목 vs 수익 종목 비중
4. **총평가액 추이** — `updatedAt` 스냅샷을 쌓으면 자산 곡선(선택)

#### 외부 데이터가 있어야 되는 것

- **섹터 노출** — `accountHoldings`에 섹터 컬럼이 없음. Yahoo Finance 등으로 종목→섹터 매핑을 붙여야 "반도체에 60% 몰림" 같은 게 나온다. (2단계)

#### 기존 기능과 다른 점

- `/account`: 종목 나열 (개별 뷰) → 이건 **합산·비중·경고** (포트폴리오 뷰)
- Gemini 리스크 평가(`riskAssessments`): 종목 하나의 정성적 리스크 → 이건 **전체 구성의 정량적 편중**

#### 확인 필요

해외 종목의 원화 환산(`evalAmountKrw`)이 채워져 있어야 국내+해외를 한 기준으로 합칠 수 있다. 비어 있으면 환율을 별도로 끌어와야 함.

### 2. 매매 전 체크리스트 게이팅

**한 줄 요약:** 매수 일지를 저장하기 **전에** 내 리스크 체크 항목과 투자 원칙을 확인하도록 강제해서, "그냥 지르는" 매매를 구조적으로 막는 것.

#### 이미 있는 재료 (중요)

앱에는 이미 두 가지가 있다:

1. **`journals.riskChecks`** — `RISK_CHECKS` 6개 항목이 정의돼 있음
   (`entryReason` 진입근거 / `stopLoss` 손절선 / `positionSize` 포지션크기 / `earningsDate` 실적발표일 / `marketDirection` 시장방향 / `invalidation` 시나리오무효화 조건)
2. **자유 메모** — `principles`(투자 원칙), `riskCriteria`(리스크 기준), `marketNotes`(장중 할일)

#### 지금의 문제: 전부 "사후(事後)"다

- `riskChecks`는 **선택 입력**이라 체크 안 하고 저장해도 그만
- 그 결과를 나중에 `mistakes.ts`가 사후 분석: "손절선(`stopLoss`) 없이 손실난 매매", "진입근거(`entryReason`) 없이 한 매매"
- 즉 **실수를 저지른 뒤에야 지적**한다. 정작 막아야 할 순간(매수 직전)엔 아무 마찰이 없다.

게이팅 = 이 순서를 뒤집어 **저장 직전에 강제**하는 것.

#### 어떻게 동작하나

**1) 대상 한정** — `tradeType === 'buy'`(필요시 `'sell'`)일 때만. `analysis`/`plan`/`reflection`엔 게이트 없음. (실수는 실제 진입에서 나오므로)

**2) 게이트 UI** — 저장 버튼을 누르면 확인 단계가 뜬다:
- `riskChecks` 6개 항목 체크박스 (미체크 항목 강조)
- 내 `principles`·`riskCriteria` 자유 메모를 **읽고 넘어가도록** 옆에 표시 (원칙 리마인더)

**3) 강도 두 단계 — 소프트 게이트 권장**
- **소프트(권장):** 미체크가 있으면 경고 + "그래도 저장" 확인. 마찰은 주되 막지는 않음. `draft` 저장은 게이트 면제(초안 탈출구)
- **하드:** 필수 항목(예: `stopLoss`, `entryReason`) 미체크면 저장 불가. 규율은 세지만 급할 때 답답함

**4) 자유 메모의 체크 항목화(선택, 2단계)** — `principles`/`riskCriteria`의 각 줄을 체크 가능한 항목으로 승격시켜 "내가 세운 원칙"까지 게이트에 포함.

#### 왜 가치 있나 — 루프가 닫힌다

`riskChecks`는 이미 `mistakes.ts`(사후 분석)와 `journal/stats`(리스크 준수율)에서 쓰인다. 진입 시점에 강제하면:

- 데이터 품질이 올라가 사후 분석이 정확해지고
- "손절선 안 정하고 산 매매의 승률" 같은 통계가 **비어 있지 않게** 됨
- 규율(진입 전) → 기록(체크) → 회고(사후 분석)가 하나로 연결된다

#### 확인 필요

하드 게이트는 사용성을 해칠 수 있음. 혼자 쓰는 앱이라 **소프트 게이트 + `draft` 면제**로 시작하고, 답답하지 않으면 특정 항목만 하드로 올리는 게 안전.
